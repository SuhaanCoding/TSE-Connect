# TSE Connect interaction contract

Scope: member bios and keywords, LinkedIn background, profile display, directory search and personal recommendations. Existing authentication, opt-in and contact visibility remain authoritative in the existing server routes and Supabase policies.

| Capability     | Canonical owner                      | Source of truth              | Allowed variants                   | Verification                          |
| -------------- | ------------------------------------ | ---------------------------- | ---------------------------------- | ------------------------------------- |
| Form           | Input, KeywordsField; lib/profile.ts | Member profile API           | Settings edit; onboarding review   | Validation tests, browser save/reload |
| Select/Listbox | Native graduation-year select        | Existing Settings/StepVerify | Platform-owned popup               | Keyboard and open popup inspection    |
| Scrollbar      | app/globals.css                      | DESIGN.md mirrored tokens    | Global baseline                    | Computed style                        |
| Toast          | components/ui/Toast.tsx              | Existing profile save flow   | Success; inline persistent failure | Browser success/failure               |
| CRUD           | /api/alumni PUT                      | Authenticated user and RLS   | Update own editable profile fields | Tests and DB transaction checks       |

Keywords are optional, limited to 10 entries of 40 characters each, trimmed and deduplicated without case sensitivity. Commas separate values. They are plain text, visible and searchable to signed-in members under the existing profile access policy. Clearing all values saves an empty list. Omitted keywords preserve stored values, including older onboarding clients.

Members update keywords in Settings, remain on Settings after save and receive the existing success toast. Validation focuses the Keywords input; network/server failures keep entered values and show a persistent retry instruction. Duplicate saves are prevented. Directory summaries show three keywords and an overflow count; full profiles show every keyword as a link to the directory query. Empty profiles gain no placeholder section.

Company history is scraper-owned. Member edit and onboarding views show the current company read-only with a LinkedIn refresh explanation. The member API omits current_company and past_companies regardless of input; a database trigger also rejects direct member changes. Service-role scraping remains able to refresh company history. Keyword edits never modify scraped career history or account ownership.

Directory search includes keywords alongside names, roles and current/past companies. Committed search/filter/page state stays in the URL. Search debounces at 300ms, suppresses IME composition and aborts stale requests. Clearing search resets page, cancels pending work and returns focus to the input. Search errors show an explicit retry action, not a false empty result.

Desktop and narrow-screen verification must cover save/reload, keyword links, no-results/clear, keyboard focus, failed save recovery, validation limits and read-only company fields. API tests cover malformed data, preservation of omitted fields and attempts to overwrite scraper-owned fields.

Member bios are optional plain text, limited to 1,000 characters. Blank values clear the bio; omitted values preserve it. LinkedIn About is capped at 6,000 characters, and combined job/project descriptions at 18,000. Scraping only writes visible, nonempty background text and never overwrites member-authored bio or keywords. All scraped background fields are read-only for member accounts.

Search ranks the authenticated roster using field-weighted TF-IDF cosine similarity across names, roles, company history, member bio, keywords and LinkedIn background. Exact name/company lookup receives priority. Deliberate keywords and bios outweigh scraped background; each field is normalized, term repetition is capped, common terms are discounted, and domain acronyms map to canonical concepts. Specific phrases supply readable reasons rather than isolated fragments. The user’s November 10 request supersedes the earlier positive-match-only preview: ranked discovery retains all distinct people visible to the authenticated directory, including unconfirmed, opted-out and zero-overlap profiles. Exclude the viewer and duplicate canonical LinkedIn identities; prefer a claimed/opted-in copy. An unclaimed, unconfirmed sheet placeholder without a URL or authored content may be suppressed only when exactly one linked identity has the same whitespace-normalized full name, role, employer and entire history of at least three past employers, with no conflicting graduation year. Never merge on a name alone or delete roster records. Preserve existing RLS and contact sanitization in lib/directory.ts. Responses omit full scraped text, login email, auth ID and scrape timestamps. Opted-out profiles cannot receive a starter; their existing directory visibility is unchanged.

lib/network.ts owns goals, scope, ranking reasons, random draws and message templates. Editable category data lives in data/company-categories.json, with normalization, boundary-aware regex matching and conservative typo handling in lib/company-taxonomy.ts. Matched alias and method remain attached to each tag. Unknown names and ambiguous fuzzy matches stay unclassified; an approximate match never changes stored employer history. Shared interests use weighted TF-IDF cosine overlap. Full-network ranking keeps small meaningful cosine scores rather than flattening them into zero-score ties; generic-only overlap still supplies no interest evidence. Career perspective adds explicit role-title seniority (20%) and network opt-in (15%); peer exchange adds cohort proximity (20%) and opt-in (10%). These are configurable relevance heuristics, not financial EV, reply likelihood or measures of a person’s worth. The production layout omits the proxy banner and internal coverage diagnostics; category tag details retain the approximate classification and source information. Reasons describe actual evidence, never an inferred job opening or referral offer. Unknown profiles remain exploratory, with stable alphabetical tie breaks.

/api/alumni/matches ranks the full RLS-visible corpus and paginates by 12 without a 100-person cap. Filters use OR within category/company sets and AND across scopes/year/opt-in; a query reranks everyone rather than silently hiding weak matches. URL state includes goal, filters and page; back/forward restores it. Preserve old search links by opening Browse directory when legacy query parameters have no explicit view. Search is IME-safe, debounced 300ms and cancels stale requests. Requests time out with an actionable retry. Empty filters, load/error states and page clamping are explicit.

Smart shuffle draws three without replacement from the top 20 remaining matches; Wildcard draws from farther down the remaining pool when it is large enough. Original ranks remain visible. Seen IDs reset on filter changes and after exhaustion; a small remaining pool may show fewer than three people. Random draws are transient; the shareable URL restores the ranking and filters. No points, response probabilities or claims about hiring accuracy.

NetworkExplorer owns the editable message panel, reusing AlumniCard, Button and SearchBar. The production layout is search, filters/categories, optional personalization, then Your network. The shortlist and save-for-outreach actions are removed. Results use a compact alumni/picks count and existing pagination; discovery modes expose their selected state. No shortlist IDs are written to localStorage. sessionStorage holds editable drafts scoped to viewer and recipient, at most 2,000 characters, until that browser session ends. Drafts are plain text, never sent automatically, and copy failure offers manual selection. No credentials enter either storage. Existing Settings and profile contact policy are authoritative for actual outreach links. Native selects and details retain standard keyboard behavior and platform popup geometry.

Graduation lifecycle is owned by lib/education.ts and the existing scrape pipeline. Only explicit, already-ended UCSD degree/program dates may replace a school label; future, ambiguous, conflicting or non-degree education requires review. Current-year dates without a month stay uncertain. An import uses a conditional graduation-label write to avoid overwriting a concurrent member correction. Existing numeric graduation years are preserved; old sheet school labels cannot revert them. Education-only results report exactly the IDs and fields changed. Tests cover dates, conflicts, numeric preservation and import receipts.

Scrape recovery is owned by lib/scrape.ts and the authenticated admin routes. Runs reserve a unique active slot before starting an actor. Webhooks and admin polling use an expiring database lease, resume persisted phases after transient failures, and cannot create a second automatic recovery attempt. Callbacks are associated atomically with actor start when configured; missing callback configuration is explicit. Each input retains its provider, matched roster IDs, updated fields and unresolved reason. Matching uses requested/returned URLs, with cross-provider aliases linked only through stable numeric LinkedIn member IDs. Authored content and hidden fields are preserved, with one career consistency exception: when a verified current employer changes but its title is hidden, clear a title belonging to the old employer. A hidden title at the same normalized employer preserves the saved title. The conditional write checks the previous role and employer to avoid overwriting a concurrent correction. Concurrent LinkedIn roles select a title from the selected employer’s current experience; a profile headline or another employer’s position cannot supply it. Partial imports are labeled partial in history and have a per-profile review plus a Retry unresolved profiles action. The automatic fallback has separate live pricing verification, a $1 actor cap, and no email enrichment. Receipt access is confined to service-role admin APIs. Rollback-only database checks verify reservation uniqueness, lease exclusion/expiry and direct member access denial.

Deeper matching is an explicit ranked-discovery variant owned by ResumeMatching, ServerMatchClient and the authenticated POST /api/alumni/matches handler. Standard matching retains its lightweight GET flow. The pinned model runs inside the existing Node.js server function; members download no inference model, runtime or vector index. The scorer still combines 80% semantic cosine and 20% passage BM25, selected on the development benchmark. Directory search overrides the private goal while populated. Exact name/company lookup stays prioritized. Existing goal nudges, filters, random draws, ordinals and pagination retain their semantics. No new inference provider or paid model API is introduced.

PDF/TXT files are parsed in the tab (5 MB, 10 pages, 30,000 characters), with local validation and paste fallback. Uploaded text remains a review draft until Match this experience is pressed. Cleaned experience, goal (600 characters) and lookup (200 characters) travel only in a same-origin authenticated POST body. They never enter URLs, persistent browser storage, analytics, application logs, profile writes, shared caches or the derived alumni index. The current user request authorizes server processing and removes infrastructure/download explanations from the production UI. The brief helper says Used for matching. Not saved to your profile. Invalid files preserve the previous valid draft; stale extraction cannot overwrite a new selection or removal. Textareas auto-grow with a bounded scrollbar.

The POST handler rejects cross-origin requests, bounds streamed request bytes before JSON parsing, authenticates a confirmed directory member and reloads the current RLS-visible roster on each new query. Model weights are bundled and reused within a warm function instance. Alumni vectors stay in private Storage and are joined only by current visible IDs and source hashes. Request-specific experience and query vectors remain local to the invocation and are never placed in a shared cache. Per-instance admission bounds simultaneous inference; this is a resource guard, not a distributed rate limit. Cache or inference failures return usable word matching with a clear status. Error replies omit internal exceptions and private content.

Responses contain sanitized directory profiles and bounded stored professional evidence, never query text, query vectors, full background text or the complete passage index. Existing contact visibility remains authoritative. ServerMatchClient keeps at most two query results in tab memory, sharing identical in-flight requests and reusing results for filters, pagination and shuffling. A new context aborts a superseded request; stale results cannot replace the current view. Remove resume & goal, Standard matching, and directory unmount abort pending work and clear this transient cache. Resume editor values survive switching to Standard matching until removal or leaving the directory. Refresh network replaces the transient result cache. The older paged semantic GET protocol remains available for already-open older clients; the current UI never invokes the browser encoder.
